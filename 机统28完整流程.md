## 一、状态机（7 个状态 + 无需专检分支）

```
                 ┌──────────────────────────── 无需专检（special 为空） ────────────────────────┐
                 │                                                                             ▼
提报 → 0待施修 → 6已开工 → 1待派工 → 2待互检 ─┬─→ 3待专检 ──→ 4已完成 → 5已放行
                                              │                                              ▲
                                              └────────────── 后端自动 ──────────────────────┘
```

| 码 | 状态   | 颜色 | 说明                                                |
| -- | ------ | ---- | --------------------------------------------------- |
| 0  | 待施修 | 橙   | 刚提报                                              |
| 6  | 已开工 | 浅蓝 | 开工点名完成                                        |
| 1  | 待派工 | 蓝   | 自检完，等派工                                      |
| 2  | 待互检 | 紫   | 派工完，互检人作业                                  |
| 3  | 待专检 | 靛蓝 | 互检完，专检作业                                    |
| 4  | 已完成 | 绿   | 互检+专检通过（**无需专检则互检后直接到此**） |
| 5  | 已放行 | 青绿 | 最终放行 / 可离段                                   |

退回：**互检不通过 → 1待派工**；**专检不通过 → 2待互检 或 0待施修**。

## 二、completeStatus（流转触发码）

每个环节提交时 **前端写死传固定值**，后端据此推进状态：

| 提交环节                              | 传 completeStatus | 后端推进逻辑（关键）                                                                          |
| ------------------------------------- | ----------------- | --------------------------------------------------------------------------------------------- |
| 开工 / 自检提交（施修页、开工点名页） | `2`             | → 状态 1 待派工（或派工后直达 2 待互检）                                                     |
| **互检提交**                    | **`3`**   | 有专检人 → 状态**3 待专检**；**专检人为空/配置无需专检 → 直接到 状态 4 已完成** |
| 专检提交                              | `4`             | → 状态 4 已完成                                                                              |
| 最终放行                              | —                | → 状态 5 已放行                                                                              |

## 三、「如果不需要专检」怎么做？

### 规则（完全由后端决定是否跳专检）

前端无需改任何流程，**在最开始的『施修提交』阶段不选专检人即可**。后端收到互检提交 `completeStatus=3` 时：

- 若 `specialInspectionPersonnel` **有值** → 按正常流程走 **3 待专检**
- 若 `specialInspectionPersonnel` **为空** → 后端直接跳 **4 已完成**（跳过 3 待专检）

### 前端操作路径（两处入口，任选其一）

#### ▶ 方式一：施修页（jt_repair）不填专检人

| 步骤 | 操作                                                                                                            |
| ---- | --------------------------------------------------------------------------------------------------------------- |
| ①   | 工作界面 → 检修作业 → 选机车 → 检修作业-明细 → 作业进度 → 待施修（0）→ 进入「机统28施修页」               |
| ②   | 填施修内容、故障部件、**选互检人员**（必填）                                                              |
| ③   | **不选「专检人员」**（下拉提示『无专检人员信息』时直接留空）—— 对应 `specialInspectionPersonnel=null` |
| ④   | 提交 → 后续派工 / 互检照常；**互检人提交后** → 后端自动跳 `4 已完成`，不会出现在「待专检」列表        |

> 代码参考：[jt_repair.dart:80-82](file:///d:/jcjx/jcjx-phone/lib/routes/production/jt_repair.dart#L80-L82) + [jt_repair.dart:392-419](file:///d:/jcjx/jcjx-phone/lib/routes/production/jt_repair.dart#L392-L419)（专检人员为空只 Toast 提示，不阻断提交）

#### ▶ 方式二：范围作业设置互检/专检人页不填专检人

检修作业明细 → 作业项 → 设置互检专检人页面 → **选互检、不选专检**，后续同理自动跳。

## 五、各状态页面 & 操作人

| 状态     | 操作人          | 页面                       | 做什么                                                                         |

| 0 待施修 | 施修人          | 机统28施修页               | 填施修内容、配件、加工方法，上传照片；**是否选专检决定后续走不走状态 3** |

## 七、关键规则

1. **跳专检由后端决定**：前端 **不传/传空 `specialInspectionPersonnel`**，后端收到互检提交 `completeStatus=3` 后直接推 `4已完成`，前端不用改页面逻辑。
2. **权限菜单自动补位**：首页图标每行 3 个，某图标无权限则 **隐藏**，后面的图标 **自动前移**，仅行尾不足 3 个时空白补齐。
3. **派工两种模式**：**单人派工**直接推进到 2 待互检；**班组派工**需班组成员「领活」后归属个人。
4. **工序 / 排程节点绑定**：每条机统28 绑定 `trainEntryCode`（入段编码），展示时连带 **工序节点 repairMainNodeName + 排程节点 scheduleNodeName**，便于定位机车当前阶段。
